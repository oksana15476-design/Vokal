# Vokal Director

`Vokal Director` - русскоязычный моковый AI-директор для подготовки песни к репетиции группы или уроку музыки.

Продуктовая идея: пользователь загружает песню, выбирает сценарий и получает рабочий `Stage Pack` с партиями, аккордами, MIDI, stems, минусом, кликом, репетиционными треками, предупреждениями и предложениями AI-директора.

## Текущий статус

В репозитории уже есть кликабельный frontend-прототип на моковых данных.

Работает:

- сценарии `Для группы` и `Для обучения`;
- выбор цели обработки;
- моковая загрузка файла;
- демо-проекты;
- настройка состава группы или учебной задачи;
- имитация многошаговой обработки;
- экран `Stage Pack`;
- просмотр материалов;
- версии аранжировки;
- сомнительные такты и статусы проверки;
- AI-действия, которые меняют моковое состояние;
- моковая выдача материалов музыкантам или ученикам;
- пересборка ZIP и репетиционных треков после правок;
- видимость ограничений состава, ученика и учебных заданий;
- цикл `После репетиции` / `После урока`;
- удаление исходника и результатов в моковом privacy-слое;
- оценка сложности обработки;
- блок приватности и согласия;
- откат к предыдущей версии со снимком материалов;
- диалог AI-директора с историей реплик;
- предупреждения обработки и низкой точности разбора;
- проверка формата и размера файла при выборе;
- ошибка шага обработки с повтором (срабатывает на тяжелом исходнике).

Пока не работает реально:

- обработка аудио;
- source separation;
- транскрипция в MIDI;
- MusicXML/PDF rendering;
- настоящие загрузки и скачивания;
- backend API;
- авторизация;
- платежи;
- реальные AI-вызовы;
- реальные ссылки общего доступа.

## Запуск

```bash
npm install
npm run dev
```

Локальный адрес обычно:

```text
http://127.0.0.1:5173/
```

## Проверки

```bash
npm run typecheck
npm run test -- --run
npm run build
git diff --check
```

Те же четыре проверки гоняет CI (`.github/workflows/ci.yml`) на каждый push и pull request.

`npm run test` ограничен продуктовыми тестами в `src`, чтобы не запускать перенесенные служебные тесты из `.claude/skills`.

Тесты делятся на два слоя:

- `src/services/mockServices.test.ts` — доменные правила: создание проектов, AI-действия,
  устаревание материалов, откат версий, валидация загрузки, оценка обработки;
- `src/App.test.tsx` — интерфейс (`jsdom` + `@testing-library/react`): что пользователь
  действительно видит на экране. Этот слой существует потому, что несколько блоков
  однажды тихо исчезли из вёрстки, оставшись в доменной модели.

Линтера нет; вместо него в `tsconfig.json` включены `noUnusedLocals` и `noUnusedParameters`.

## Как проверить руками

1. `npm run dev`, открыть `http://127.0.0.1:5173/`.
2. Нажать `Открыть готовый разбор` — пройдут шаги обработки, откроется `Stage Pack`.
3. Вкладка `AI-директор` → любое действие: появится новая версия, реплика в диалоге,
   а часть материалов получит пометку «нужно пересобрать».
4. Клик по предыдущей версии в списке — материалы вернутся к её состоянию.
5. На главном экране выбрать файл с расширением не из списка — появится объяснение отказа.
6. Файл тяжелее 20 МБ даст низкое качество исходника: шаг разделения на аудиослои
   упадет с кнопкой `Повторить шаг`.

## Архитектурная позиция

Готовые модели и сервисы используем там, где они уже сильны: stems, transcription, beat tracking, MusicXML preview и LLM reasoning.

Своим продуктовым ядром делаем:

- `SongGraph`;
- `Arrangement Engine`;
- `Pedagogy Engine`;
- `Confidence and Review Engine`;
- `Version Engine`;
- `Export and Distribution Rules`;
- `DirectorAction` DSL.

Если готового API или модели не хватает по качеству, правам или музыкальной логике, слой остается за Vokal и строится как собственный модуль.
