# Vokal Director

`Vokal Director` - русскоязычный моковый AI-директор для подготовки песни к репетиции группы или уроку музыки.

Продуктовая идея: пользователь загружает песню, выбирает сценарий и получает рабочий `Stage Pack` с партиями, аккордами, MIDI, stems, минусом, кликом, репетиционными треками, предупреждениями и предложениями AI-директора.

## Текущий статус

В репозитории уже есть кликабельный frontend-прототип на моковых данных.

Работает:

- сценарии `Для группы` и `Для обучения`;
- выбор цели обработки;
- выбор файла с чтением его свойств в браузере;
- демо-проекты;
- настройка состава группы или учебной задачи;
- шаги обработки с честным разделением: выполняемые и пропущенные;
- экран `Stage Pack` с полосой метрик песни;
- пультовая панель: транспорт, форма песни, дорожки, аккорды;
- точность разбора цифрами рядом с полосой, а не только цветом;
- состав как люди с ограничениями;
- три уровня сложности для школ;
- список материалов с фильтром и постраничностью;
- версии аранжировки и откат на любую глубину со снимком материалов;
- сомнительные места и статусы проверки;
- действия AI-директора, в том числе сборка одной версии сразу из
  нескольких предложений;
- разговор с директором репликами, с честным ответом на непонятую команду;
- тосты с отменой действия;
- подтверждение необратимого удаления;
- выдача материалов музыкантам или ученикам;
- пересборка ZIP и репетиционных треков после правок;
- цикл `После репетиции` / `После урока`;
- удаление исходника и результатов в privacy-слое;
- блок приватности и согласия;
- предупреждения обработки и низкой точности разбора;
- проверка формата и размера файла при выборе.

Пока не работает реально:

- обработка аудио;
- source separation;
- транскрипция в MIDI;
- MusicXML/PDF rendering;
- настоящие загрузки и скачивания;
- backend API;
- авторизация;
- платежи;
- реальные AI-вызовы;
- реальные ссылки общего доступа;
- хранение песен между сеансами.

Органы управления, за которыми ничего нет, **выключены и говорят почему**, а
не нажимаются вхолостую: воспроизведение, Solo и Mute на дорожках, скачивание
ZIP. Это осознанное правило, а не недоделка: кнопка, которая нажимается и
ничего не делает, — обещание.

Коммерческих поверхностей из бренд-бука (тарифы, `Band Pro`, счетчик пакета)
и оценок времени обработки в интерфейсе нет намеренно: ни оплаты, ни
обработки не существует, а цена и срок там, где за ними ничего не стоит, —
ложное обещание. Сторож честности в `src/App.test.tsx` валит сборку на таких
строках. Решение записано в
`docs/superpowers/plans/2026-09-09-design-system-adoption.md`.

## Дизайн-система

Интерфейс собран по бренд-буку «Пульт» (направление D) из бандла владельца.
Токены — `docs/design/tokens.json`, правила и чеклист ревью —
`docs/superpowers/specs/2026-09-09-brandbook-screens.md`.

Ключевые правила, которые проверяются тестами и браузером:

- графит — главное действие шага, бирюза — подтверждение результата
  системы, контур — вторичное, красный — необратимое; больше одного
  графитового CTA на экране не бывает;
- все, что связано со звуком, живет на одной графитовой панели;
- уверенность подписана процентом: цвет не единственный сигнал;
- компоненты берут цвет из ролей, а не из хексов;
- контраст текста не ниже 4.5:1, тач-цели не меньше 44 px.

## Запуск

```bash
npm install
npm run dev
```

Локальный адрес обычно:

```text
http://127.0.0.1:5173/
```

## Проверки

```bash
npm run typecheck
npm run test -- --run
npm run build
git diff --check
```

Те же четыре проверки гоняет CI (`.github/workflows/ci.yml`) на каждый push и pull request.

`npm run test` ограничен продуктовыми тестами в `src`, чтобы не запускать перенесенные служебные тесты из `.claude/skills`.

Тесты делятся на два слоя:

- `src/services/mockServices.test.ts` — доменные правила: создание проектов, AI-действия,
  устаревание материалов, откат версий, валидация загрузки, оценка обработки;
- `src/App.test.tsx` — интерфейс (`jsdom` + `@testing-library/react`): что пользователь
  действительно видит на экране. Этот слой существует потому, что несколько блоков
  однажды тихо исчезли из вёрстки, оставшись в доменной модели.

Линтера нет; вместо него в `tsconfig.json` включены `noUnusedLocals` и `noUnusedParameters`.

## Как проверить руками

1. `npm run dev`, открыть `http://127.0.0.1:5173/`.
2. Нажать `Открыть демо-разбор` — пройдут шаги обработки, откроется `Stage Pack`.
3. Вкладка `AI-директор` → любое действие: появится новая версия, реплика в диалоге,
   а часть материалов получит пометку «нужно пересобрать».
4. Клик по предыдущей версии в списке — материалы вернутся к её состоянию.
5. На главном экране выбрать файл с расширением не из списка — появится объяснение отказа.
6. Файл тяжелее 20 МБ даст низкое качество исходника: шаг разделения на аудиослои
   упадет с кнопкой `Повторить шаг`.

## Стенд

Площадка — **Timeweb**, app-хостинг из Docker.

```bash
docker build -t vokal-stand .
docker run --rm -p 8080:80 vokal-stand
```

Образ двухступенчатый: сборка на `node:22-alpine`, отдача статики через `nginx`.
Внутри сборки прогоняются typecheck, тесты и build — образ не соберется из красного
дерева, поэтому на интервью нельзя увезти непроверенный прототип. Конфигурация
nginx в `docker/nginx.conf`: `noindex` заголовком, долгий кеш для хешированных
ассетов, отсутствие кеша для документа.

> Образ **не проверен сборкой**: в среде разработки, где он писался, демон Docker
> недоступен. Первую сборку нужно прогнать на машине с Docker или прямо в Timeweb.

Запасной путь — GitHub Pages: workflow `Выложить стенд` в разделе Actions, запуск
только вручную через `Run workflow`. Автоматической выкладки на push нет намеренно:
владелец решает, что видно снаружи.

Сборка использует относительные пути (`base: "./"` в `vite.config.ts`), поэтому
открывается и по корню домена, и по вложенному пути. Страница помечена
`noindex, nofollow`: запрет индексации действует при любом правовом ответе,
см. `docs/LEGAL_POSITION.md`.

## Словарь интерфейса

Текст прототипа не обещает цен, тарифов и сроков обработки. Вместо тарифной оси
используется ось зрелости данных:

- **собрано** — содержимое есть в прототипе, его можно открыть;
- **имитация** — действие работает, но меняет только состояние прототипа;
- **нужна обработка** — пока только карточка материала, содержимое появится
  с настоящей обработкой звука.

Формулировки утверждены связкой копирайтер -> главред. Регресс ловит тест
`src/App.test.tsx` в блоке «честность текста»: он падает, если в интерфейс
вернутся слова о тарифах и сроках, жаргон «мок» или буква «ё» (дом-стиль — без «ё»).

## Архитектурная позиция

Готовые модели и сервисы используем там, где они уже сильны: stems, transcription, beat tracking, MusicXML preview и LLM reasoning.

Своим продуктовым ядром делаем:

- `SongGraph`;
- `Arrangement Engine`;
- `Pedagogy Engine`;
- `Confidence and Review Engine`;
- `Version Engine`;
- `Export and Distribution Rules`;
- `DirectorAction` DSL.

Если готового API или модели не хватает по качеству, правам или музыкальной логике, слой остается за Vokal и строится как собственный модуль.
