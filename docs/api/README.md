# Контракт API

Контракт между фронтендом и сервером Vokal Director. Схема — `docs/api/openapi.json`,
из нее генерируется клиент (решение по бэкенду от 2026-09-10 в `docs/architecture.md`:
источник правды для клиента — OpenAPI, а не руками написанные типы).

Схемы живут в `server/app/api/schemas/`, роутеры — в `server/app/api/routes/`,
сборка — `server/app/api/router.py`.

## Состояние: схема настоящая, реализации почти нет

Из 40 операций по-настоящему работают **три**. Остальные отвечают `501`.

Это не заготовка «на потом». Схема запроса и ответа у каждого адреса полная:
по ней можно генерировать клиент, писать экраны и спорить о полях. Чего нет —
это логики за адресом, и адрес говорит об этом прямо, а не возвращает
правдоподобные данные.

Правило то же, что в интерфейсе: орган управления, за которым ничего нет,
выключен и говорит почему. Мок в ответе сервера хуже отказа — фронтенд примет
его за результат, экран покажет «готово», и расхождение вскроется у
пользователя, а не в разработке.

Честность отказа держит тест `server/tests/test_api_contract.py`:
`test_every_stub_endpoint_answers_not_implemented` обходит все опубликованные
адреса и валит сборку, если хоть один ответил `200` выдумкой.

## Как подключается

Роутер подключается одной строкой — место уже помечено комментарием в
`server/app/main.py`:

```python
from app.api.router import api_router
app.include_router(api_router, prefix="/api")
```

**Пока эта строка не раскомментирована, адреса не отвечают:** `main.py` —
зона батча каркаса, и этот батч ее не трогал. До подключения контракт живет в
схеме, тестах и приложении `app.api.contract_app`.

## Как обновить схему

```bash
cd server
.venv/bin/python -m app.api.contract_app > ../docs/api/openapi.json
```

Выгруженный файл сверяется тестом с тем, что отдает приложение
(`test_exported_openapi_is_current`). Забыть обновить `openapi.json` после
правки схемы не получится — прогон покраснеет.

## Соглашения

**Имена полей — camelCase.** Так устроен домен фронтенда
(`src/domain/types.ts`), из которого растет клиент.

**Идентификаторы — непрозрачные строки.** Сервер выдает UUID, у демо-проектов
идентификаторы читаемые. Клиент не должен разбирать их содержимое.

**Незнакомое поле в теле — ошибка `422`,** а не тихо отброшенное значение.
Продукт уже обжигался на тихой подмене настроек пользователя умолчанием
(комментарий к `BandSetup` в `types.ts`); опечатка в имени поля обязана быть
слышной.

**Ошибка всегда выглядит одинаково** (форма задана `server/app/core/errors.py`):

```json
{
  "error": {
    "code": "not_implemented",
    "message": "Обработка звука не запускается: обработчиков еще нет.",
    "requestId": "0f1c…",
    "details": {
      "endpoint": "POST /api/projects/{project_id}/jobs",
      "missing": ["очередь заданий и обработчики", "разделение слоев, транскрипция, сборка материалов"],
      "docs": "docs/api/README.md"
    }
  }
}
```

Коды: `validation_error` (422), `not_found`, `forbidden`, `unauthorized`,
`conflict` (409), `payload_too_large` (413), `rate_limited` (429),
`not_implemented` (501), `internal_error`, `service_unavailable`.

У `validation_error` в `details.fields` лежит список `{field, reason}`.
Присланного значения там нет намеренно: тело запроса наружу и в логи не
возвращается (`docs/DELETION_AND_RETENTION_DESIGN.md`, «Политика логирования»).

**`501` означает ровно одно:** адрес объявлен, схема настоящая, логики нет.
В `details.missing` перечислено, чего именно не хватает — по нему видно, чей
это батч.

## Решения, зашитые в контракт

### Загрузка

Файл в теле запроса не передается. `POST /api/uploads` заводит запись и
возвращает подписанную ссылку в хранилище; файл уходит туда напрямую, минуя
процесс API. Иначе каждая песня занимала бы процесс на все время передачи.

Формат проверяется по расширению, а не по MIME: браузеры сообщают тип
вразнобой, и отказ по MIME отсекал бы нормальные файлы. Так же сделано на
фронтенде.

Предела длительности нет, и в ответе это сказано полем `maxDurationSeconds:
null`, а не молчанием: подобрать предел можно только по себестоимости
настоящей обработки, а обработки еще нет.

### Согласие

`POST /api/projects` принимает `consent: {accepted, versionId}`. Версия
обязательна и проверяется по реестру `server/app/api/consent_versions.py` —
зеркалу `src/domain/consent.ts`. Неизвестная версия — `422`.

Без версии запись «согласие получено» остается без предмета: текст на экране
меняется, а прочитать старое согласие потом неоткуда. Задним числом это не
чинится.

Тест `test_consent_registry_matches_frontend` сверяет идентификаторы, тексты и
контрольные суммы с фронтендом: правку формулировки нельзя внести, не тронув
версию с обеих сторон.

### Сценарий, цель и настройка обязаны сойтись

`scenario`, `goalId` и `setup.kind` проверяются на согласованность. Урок с
целью группы — не опечатка пользователя, а разошедшееся состояние экрана, и
молча выбрать «правильное» значение нельзя: верным может быть любое из трех.

### Обработка

Прогресс читается поллингом `GET /api/jobs/{job_id}`. Интервал говорит сервер
(`pollAfterMs`), а не выбирает клиент. У завершенного задания поле пустое —
спрашивать больше не о чем.

Шаг со статусом `skipped` не будет выполнен вовсе. Это отдельный статус, а не
разновидность «готово»: несделанное не выдается за сделанное.

`POST /api/projects/{project_id}/jobs` принимает заголовок `Idempotency-Key`:
повторный запуск обработки — это повторное списание стоимости, а не безобидный
дубль. Тот же заголовок принимает `POST /api/projects`.

### Stage Pack

`GET /api/projects/{project_id}/stage-pack` возвращает материалы, разбор и
места для проверки одним ответом. Материалы без разбора и без мест проверки
читаются как проверенный результат, хотя любой автоматический результат —
черновик.

### Директор

Действие приходит кодом из закрытого списка `DirectorActionId`. Незнакомый код
— `422`, а не попытка угадать намерение: музыкальные изменения применяет
детерминированный слой, LLM только объясняет и выбирает действие.

Пакет действий (`/director/actions/batch`) дает **одну** версию с общим
перечнем изменений. Те же действия по одному дали бы цепочку промежуточных
версий и столько же пересборок материалов.

### Версии и откат

Откат идет на версию, указанную в адресе, — глубина не ограничена. Откат
создает новую версию, а не переписывает историю: иначе по списку версий нельзя
понять, почему материалы вдруг стали прежними.

В ответе отката есть `staleArtifactIds` — материалы, снимка которых в целевой
версии не было и которые придется пересобрать.

### Выдача

Ссылка ведет на наш адрес и содержит отзываемый токен; подписанная ссылка на
объект хранилища наружу не выдается никогда. Требование
`docs/DELETION_AND_RETENTION_DESIGN.md`: подписанную ссылку невозможно
отозвать, и без этого «удалить результаты» не закрывает уже выданный доступ.

Отсюда же `revokedAt` и статус `revoked` у ссылки, и отдельный
`DELETE /api/projects/{project_id}/share-links/{link_id}`.

### Удаление

Две раздельные операции, а не одна с параметром: у них разный смысл и разные
последствия, и слитый адрес однажды выполнит не ту.

Обе требуют явного `confirm: true` — пустое тело необратимую операцию не
запускает. Обе отвечают `202`, а не `200`: пока хранилище не подтвердило
удаление, правильное состояние — «удаление выполняется», и его показывает
`GET /api/projects/{project_id}/deletion-status`.

Состояния удаления: `present`, `purge_requested`, `purged`, `purge_failed`.
Флага «удалено» недостаточно; `purge_failed` — инцидент, а не строка в логе.

Повторный запуск на уже удаленном проекте завершается успехом: операция
идемпотентна.

## Расхождение с `src/domain/types.ts`: латинские ключи

В контракте **латинские ключи вместо русских подписей**. В `types.ts` роль и
уровень музыканта записаны по-русски (`"гитара"`, `"средний"`), а тот же
уровень в `BandLineup` уже латиницей (`"beginner"`). Через границу API нельзя
гонять отображаемую подпись как ключ данных — ровно на этом продукт один раз
обжегся.

Тот же выбор сделан в `server/app/db/enums.py`, так что API и база говорят на
одном языке. **Фронтенду предстоит применить таблицу соответствия** — это
работа, и она вынесена владельцу как развилка (см. ниже).

| Поле `types.ts` | Значение на экране | Ключ в API |
| --- | --- | --- |
| `Musician.role` | вокал / гитара / бас / клавиши / барабаны / бэк-вокал | `vocal` / `guitar` / `bass` / `keys` / `drums` / `backing_vocal` |
| `Musician.level` | начинающий / средний / продвинутый | `beginner` / `middle` / `advanced` |
| `BandLineup.bass` | 4 strings / 5 strings | `4_strings` / `5_strings` |
| `StudentProfile.level` | начальный / средний / сильный | `starter` / `middle` / `strong` |
| `StudentProfile.notationReading` | не читает / простые ноты / уверенно | `none` / `simple` / `confident` |
| `TeacherProfile.format` | индивидуальный урок / группа / школьный ансамбль | `individual` / `group` / `school_ensemble` |
| `Lesson.desiredDifficulty` | проще оригинала / близко к оригиналу / сложнее оригинала | `easier` / `original_like` / `harder` |
| `ShareLink.status` | mock_created / stale | `active` / `stale` / `revoked` / `expired` |

Свободные строки (тональность, строй, стиль, домашнее задание, поля
`BandSetup` и `LessonSetup`) остались строками: закрытого списка там нет, и
придумывать его на сервере значило бы запретить пользователю его собственные
слова.

## Чего в контракте нет

Сознательно вне этого батча:

- **аутентификация.** Адреса описывают `401` и `403`, потому что проверка прав
  обязательна, но схемы аутентификации в OpenAPI нет: механизм не выбран;
- **отдельное согласие на запись с голосом ученика.** `docs/DATA_MAP.md`
  требует его отдельно от общего согласия — в контракте поля под него нет;
- **realtime-канал прогресса.** Пока только поллинг;
- **биллинг и квоты.** `costEstimate` в карточке проекта есть, операций оплаты
  нет;
- **каталог целей обработки отдельным адресом.** Схема `ProcessingGoalOut`
  описана, но кто владеет ее подписями — открытый вопрос (см. развилки).

## Развилки для владельца

1. **Латинские ключи против русских литералов.** Батч выбрал латиницу — так
   уже устроена база, и подпись не должна быть ключом данных. Цена решения:
   фронтенду нужен слой соответствия по таблице выше. Альтернатива — оставить
   в API русские литералы `types.ts` и завести расхождение между API и базой.
2. **Кто владеет текстами целей обработки** (`label`, `description`,
   `expectedOutputs`). Если сервер — тексты проходят связку копирайтер →
   главред и появляется адрес каталога. Если фронтенд — из `ProjectOut` уходит
   вложенный объект и остается один `goalId`.
3. **Предел длительности загружаемого файла.** Сейчас его нет. Число можно
   назначить только вместе с себестоимостью настоящей обработки.
4. **Срок жизни выданной ссылки по умолчанию.** В запросе поле необязательное;
   умолчание сервиса не назначено.
5. **Остается ли разбор песни после `delete-source`.** Сейчас в описании
   операции сказано прямо: исходник удален, разбор остался и по нему можно
   восстановить содержание произведения. Вопрос 17 юристу в
   `docs/LEGAL_BRIEF.md` может это изменить, и тогда меняется контракт
   операции, а не только текст.
6. **Отдельное согласие на загрузку записи с голосом ученика.** Нужно ли оно
   отдельным полем в `POST /api/projects` или отдельной операцией.
